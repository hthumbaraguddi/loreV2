# Requirements Document

## Introduction

When a user creates a new Notebook in Lore, the notebook currently starts empty — the user must manually add a section before they can begin writing. This feature eliminates that friction by automatically creating a default "Page" section inside every newly created Notebook, so the user lands directly in an editable state without any extra steps.

The change is scoped to the notebook creation path only. Existing notebooks, imported notebooks, and the demo seed data are unaffected.

## Glossary

- **Notebook**: A top-level container in Lore that belongs to a Shelf and holds one or more Sections. Represented by the `Notebook` interface in `models/index.ts`.
- **Section**: A named grouping within a Notebook that holds Notes. Represented by the `Section` interface in `models/index.ts`.
- **Default Section**: The Section automatically created when a new Notebook is first created. Its title is "Page" and its type is `page`.
- **DataService**: The Angular service (`data.service.ts`) responsible for all state mutations and persistence.
- **AppComponent**: The root Angular component (`app.component.ts`) that orchestrates notebook creation via `onNotebookSaved`.
- **Note**: A content item inside a Section. Represented by the `Note` interface in `models/index.ts`.

## Requirements

### Requirement 1: Auto-create a Default Section on Notebook Creation

**User Story:** As a Lore user, I want a new Notebook to start with a default "Page" section, so that I can begin writing immediately without having to manually add a section first.

#### Acceptance Criteria

1. WHEN a new Notebook is created via the Notebook modal, THE DataService SHALL automatically add a Section with title "Page", empty subtitle, and color "purple" to the new Notebook before persisting state.
2. WHEN a new Notebook is created, THE DataService SHALL persist the Notebook together with its Default Section in a single state update.
3. WHEN a new Notebook is created, THE AppComponent SHALL set the new Notebook as the active Notebook immediately after creation.
4. THE Default Section SHALL have a unique `id` generated by `DataService.uid()` at creation time.
5. THE Default Section SHALL have an empty `notes` array at creation time.

---

### Requirement 2: Default Section Does Not Affect Existing Notebooks

**User Story:** As a Lore user, I want my existing Notebooks to remain unchanged when this feature is deployed, so that I do not lose any data or structure I have already set up.

#### Acceptance Criteria

1. WHEN the application loads an existing Notebook from persisted state, THE DataService SHALL NOT add or modify any Sections on that Notebook.
2. WHEN a Notebook is updated (rename or icon change) via the Notebook modal, THE DataService SHALL NOT add or modify any Sections on that Notebook.
3. WHEN a Notebook is imported from a JSON or HTML file, THE DataService SHALL NOT add a Default Section to the imported Notebook.

---

### Requirement 3: Default Section Does Not Affect Demo Seed Data

**User Story:** As a new Lore user, I want the demo workspace to continue appearing exactly as designed, so that the onboarding experience is not disrupted.

#### Acceptance Criteria

1. WHEN `DataService.seedDemoData()` is called, THE DataService SHALL NOT apply the Default Section logic to any Notebook created during seeding.
2. THE demo Notebook created by `seedDemoData()` SHALL continue to contain exactly the sections defined in the seed implementation.

---

### Requirement 4: Persistence of the Default Section

**User Story:** As a Lore user, I want the default "Page" section to be saved immediately when I create a Notebook, so that it is still present if I reload the app or sync to a remote store.

#### Acceptance Criteria

1. WHEN a new Notebook is created, THE DataService SHALL call `saveAll` once after both the Notebook and its Default Section have been added to state.
2. WHEN the application reloads after a Notebook was created, THE DataService SHALL restore the Notebook with its Default Section intact from persisted state.
3. WHERE Google Drive or GitHub Gist sync is enabled, THE DataService SHALL include the Default Section in the sync payload on the same save cycle as the Notebook creation.
